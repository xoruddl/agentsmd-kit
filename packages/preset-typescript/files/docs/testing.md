# 테스트

도구: Vitest, MSW.

## 무엇을 어떻게 테스트하나

| 대상 | 방법 |
| --- | --- |
| 순수 로직 (계산, 변환, 검증) | 입력과 출력을 비교하는 단위 테스트 |
| 외부 값 검증 함수 | 올바른 값, 필드가 빠진 값, 타입이 다른 값을 각각 넣어 본다 |
| 서버 통신 | MSW 로 응답을 고정하고 함수의 결과·오류 확인 |
| 시간에 따라 바뀌는 로직 | `vi.useFakeTimers()` 로 시간을 고정 |

## 원칙

- 공개된 동작을 검사한다. 내부 변수, 비공개 함수, 호출 순서처럼 구현을 바꾸면 깨지는 것을 검사하지 않는다.
- 비동기 결과는 `await` 로 기다린다. 임의의 시간만큼 기다리지 않는다.
- 네트워크는 `fetch` 를 직접 가짜로 바꾸지 않고 MSW 핸들러로 응답한다. 테스트와 개발 서버가 같은 핸들러를 쓴다.
- 처리하지 않은 요청은 실패로 만든다: `server.listen({ onUnhandledRequest: 'error' })`
- 큰 출력을 스냅샷으로 고정하지 않는다. 바뀔 때마다 갱신만 하게 되어 아무것도 검증하지 않는다.
- 버그 수정은 그 버그를 재현하는 테스트부터 쓴다.
- 테스트 이름은 한국어로, 사용하는 쪽 입장의 동작을 쓴다.
- 화면(React 등) 테스트는 그 프레임워크 프리셋 문서를 따른다.

## 예시

```ts
describe('parseMenu', () => {
  it('형식이 맞으면 메뉴를 돌려준다', () => {
    expect(parseMenu({ name: '김치찌개', price: 9000 })).toEqual({ name: '김치찌개', price: 9000 })
  })

  it('가격이 없으면 오류를 던진다', () => {
    expect(() => parseMenu({ name: '김치찌개' })).toThrow('price')
  })
})

it('서버 오류면 메뉴를 가져오지 못했다는 오류를 던진다', async () => {
  server.use(http.get('/api/menus/pick', () => new HttpResponse(null, { status: 500 })))

  await expect(pickMenu()).rejects.toThrow('메뉴를 가져오지 못했습니다')
})
```
