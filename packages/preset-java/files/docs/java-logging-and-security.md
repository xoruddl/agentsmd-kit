# 로깅 · 보안 · 의존성

## 로깅

- SLF4J 로 남긴다. Lombok 을 쓰면 `@Slf4j` 를 붙인다.
- `System.out.println`, `e.printStackTrace()` 를 쓰지 않는다. 로그 레벨과 출력 위치를 설정으로 바꿀 수 없다.
- 메시지는 `{}` 자리표시자로 쓴다. 문자열을 이어 붙이면 레벨이 꺼져 있어도 문자열을 만든다.
- 예외는 마지막 인자로 넘겨 스택 트레이스를 남긴다. `e.getMessage()` 만 남기면 원인을 추적할 수 없다.
- 같은 예외를 로그로 남기고 다시 던지지 않는다. 처리하는 한 곳에서만 남긴다. (같은 오류가 여러 번 찍힌다)

```java
// 나쁨
log.info("주문 취소: " + orderId);
log.error("결제 승인 실패: " + e.getMessage());

// 좋음
log.info("주문 취소: orderId={}", orderId);
log.error("결제 승인 실패: paymentId={}", paymentId, e);
```

| 레벨 | 언제 |
| --- | --- |
| `ERROR` | 요청이 실패했고 사람이 확인해야 한다 |
| `WARN` | 복구했지만 반복되면 문제가 된다 (재시도 성공, 기본값 사용) |
| `INFO` | 업무상 의미 있는 사건 (주문 생성, 배치 시작·종료) |
| `DEBUG` | 개발·장애 분석용 상세. 운영에서는 끈다 |

- 비밀번호, 토큰, 카드 번호, 주민등록번호 같은 민감한 값을 남기지 않는다.
- 객체를 통째로 로그에 넘기지 않는다. `toString` 에 민감한 필드가 섞여 나갈 수 있다. 필요한 식별자만 남긴다.

## 비밀값과 설정

- 비밀값(DB 비밀번호, API 키, 토큰)은 코드와 저장소에 두지 않는다. 환경변수나 비밀 관리 도구로 받는다.
- 설정 파일에는 `${DB_PASSWORD}` 처럼 참조만 적는다.
- 실제 값을 담은 파일(`.env` 등)은 저장소에 올리지 않고, 이름과 설명만 적은 예시 파일을 둔다.

## 외부 입력

- 외부에서 들어온 값(요청, 파일, 외부 API 응답)은 들어오는 경계에서 검증하고, 안쪽 로직은 검증된 값만 받는다.
- SQL 은 문자열로 이어 붙이지 않는다. `PreparedStatement` 나 JPA 의 파라미터 바인딩을 쓴다.
- 사용자 입력을 파일 경로나 셸 명령에 그대로 넣지 않는다. 경로는 `normalize()` 한 뒤 허용한 디렉터리 안인지 확인한다.
- 신뢰할 수 없는 데이터를 Java 직렬화(`ObjectInputStream`)로 읽지 않는다. JSON 같은 데이터 형식을 쓴다.
- 비밀번호는 BCrypt·Argon2 같은 검증된 해시 라이브러리로 저장한다. 암호화·해시를 직접 구현하지 않는다.

## 의존성

- 새 라이브러리는 추가하기 전에 사용자에게 묻는다. JDK 표준 API 나 이미 있는 의존성으로 되는지 먼저 확인한다.
- 버전은 Gradle version catalog(`gradle/libs.versions.toml`)에 모은다. 빌드 스크립트 여기저기에 버전 문자열을 흩어 두지 않는다.
- 테스트에만 쓰는 라이브러리는 `testImplementation` 으로 둔다.
- Gradle Wrapper(`gradlew`, `gradle/wrapper/`)를 저장소에 함께 두고, 로컬에 설치된 `gradle` 대신 `./gradlew` 로 실행한다.
