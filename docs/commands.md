# 명령 레퍼런스

## agentsmd init

프리셋의 지침 파일을 저장소에 설치하고, `git` 프리셋을 설치했으면 Git 훅을 연결한다.
Git 작업 규칙, 호스팅(GitHub), 언어 규칙, 프레임워크(React·Spring) 규칙은 따로 고른다. 함께 쓰려면 쉼표로 잇는다.
Git 훅(`.githooks/`)은 `git` 프리셋에, GitHub 템플릿(`.github/`)은 `github` 프리셋에 들어 있다. `github`은 `git`을 함께 설치하므로 `github`만 골라도 훅이 설치되고 연결된다.
어느 프리셋도 CI 설정 파일은 설치하지 않는다. CI에서 돌릴 명령과 연결 방법은 문서로 안내한다.

```bash
agentsmd init --preset git,typescript          # Git 규칙 + TypeScript 규칙
agentsmd init --preset git,github,typescript   # GitHub 템플릿까지
agentsmd init --preset git,typescript,react    # React 프론트엔드 규칙까지
agentsmd init --preset git,java                # Git 규칙 + Java 규칙
agentsmd init --preset git,spring-java         # Java·Spring Boot 서버 규칙까지
agentsmd init --preset typescript              # Git 규칙 없이 TypeScript 규칙과 프로젝트 방향 문서만
agentsmd init --preset git                     # Git 규칙만
```

| 옵션              | 설명                                                                      | 기본값 |
| ----------------- | ------------------------------------------------------------------------- | ------ |
| `--preset <이름>` | 설치할 프리셋. 여러 개는 쉼표로 잇는다. 필수                              | —      |
| `--root <경로>`   | 설치할 저장소 루트. 현재 디렉터리 기준                                    | `.`    |
| `--force`         | 직접 고른 프리셋의 파일을 이미 있어도 덮어쓰고, `AGENTS.md`를 새로 만든다 | 끔     |
| `--skip-hooks`    | `core.hooksPath`를 설정하지 않는다                                        | 끔     |

동작 순서:

1. 고른 프리셋에 필요한 프리셋이 빠져 있으면 더한다 (`github` → `git`, `java`·`typescript` → `project`, `spring-java` → `java`, `react` → `typescript`).
   필요한 프리셋은 그것을 필요로 하는 프리셋 앞에 두고, 고르지 않은 프리셋을 더했으면 출력으로 알린다.
   더한 프리셋은 직접 고른 것과 같이 다룬다. `--preset github`은 `--preset git,github`과 같고, 달라지는 것은 `--force`의 범위뿐이다(아래).
   더한 프리셋이 이미 설치돼 있어 새로 쓴 파일이 없으면 그렇다고 알린다.
2. 프리셋의 파일을 그 순서대로, 같은 경로 구조로 복사한다.
   이미 있는 파일은 건너뛰고 목록으로 알린다. 사람이 다듬어 둔 지침을 지우지 않기 위해서다.
3. 프리셋들의 문서 목록과 핵심 규칙을 합쳐 `AGENTS.md`를 만들고(이미 있으면 빠진 항목만 합친다), 그것을 불러오는 `CLAUDE.md`를 만든다.
4. 훅이 있으면 `git config core.hooksPath`로 연결한다. Git 저장소가 아니면 연결하지 않고 안내만 남긴다.
   `git init` 전에 설치했다면 `git init` 후 같은 명령을 다시 실행하면 연결된다.
5. 프리셋들이 정한 "설치 후 사람이 할 일"을 번호로 안내한다.

| 프리셋        | 내용                                                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `git`         | Git 작업 규칙·작업 흐름·리뷰 판단·문체 문서, 커밋 메시지 훅, PR 규칙 검사 스크립트(`.githooks/check-pr`), Claude Code 설정 |
| `github`      | 이슈·PR 템플릿, GitHub 사용법 문서(gh 명령, 머지 방식·룰셋 설정, CI 연결 예시)                                             |
| `project`     | 사람이 채우는 프로젝트 방향 문서(목표·범위·기술 스택). 언어 프리셋을 고르면 함께 설치된다                                  |
| `java`        | Java 코드 규칙 문서, Spotless·Gradle 검증 명령 문서                                                                        |
| `spring-java` | Java로 쓰는 Spring Boot 서버의 패키지 구조·JPA·트랜잭션·API·테스트 문서. 검증 명령은 `java`에 맡긴다                       |
| `typescript`  | 타입·구조·테스트·보안 문서, 린트·포맷·CI 명령 문서, `.nvmrc`                                                               |
| `react`       | 컴포넌트·접근성·화면 테스트·브라우저 보안 문서. 검증 명령과 `.nvmrc`는 `typescript`에 맡긴다                               |

프리셋 문서는 `docs/<프리셋 이름>/` 아래에 설치한다(`docs/git/workflow.md`, `docs/java/testing.md`). `docs/` 바로 아래는 프로젝트가 직접 쓰는 문서의 자리다.

`AGENTS.md`가 이미 있으면 덮어쓰지 않고 **빠진 항목만 합친다**. 그래서 프리셋을 어떤 순서로 나눠 설치해도 모든 문서가 지도에 오른다.

- 문서: 이미 링크된 문서는 건너뛰고 `## 문서 지도` 표 끝에 행을 더한다. 표 정렬은 다시 맞춘다.
- 규칙: 같은 문장이 없으면 `## 핵심 규칙` 목록 끝에 이어 붙인다. 번호 목록이면 번호를 잇고, 글머리표 목록이면 같은 글머리표를 쓴다.
- 검증 명령: 같은 줄이 없으면 `## 검증` 코드 블록에 더한다.
- `## 문서 지도` 절이 있으면, 빠진 절이나 표는 새로 만든다. 사람이 고쳐 둔 줄은 지우거나 바꾸지 않는다.
- `## 문서 지도` 절이 없으면 `AGENTS.md`를 바꾸지 않는다. 사람이 다른 절 이름(예: `## 작업 전 읽을 문서`)으로 쓴 지침에 같은 역할의 절을 하나 더 만들면 지침이 두 벌이 되기 때문이다.
  대신 넣지 못한 문서(표 행 모양)·규칙·검증 명령을 출력한다. 기존 절에 직접 옮기면 되고, 옮기기 전에는 `check`가 지도에 없는 문서로 알린다.
- 같은 프리셋을 다시 설치하면 아무것도 바뀌지 않는다.

나눠 설치하면 설치한 순서대로 표와 목록 끝에 쌓인다.
프레임워크 프리셋(`spring-java`, `react`)은 검증 명령을 넣지 않고 언어 프리셋에 맡긴다. 그래서 `init --preset spring-java`만 실행해도 `java`를 먼저 설치하고,
언어 프리셋의 문서가 프레임워크 문서보다 위에 온다. `--preset spring-java,java`처럼 뒤에 적어도 순서는 같다.
언어 프리셋은 프로젝트 방향 문서(`docs/project/direction.md`)를 담은 `project`를 함께 설치한다. 모든 작업 전에 읽는 문서라 언어 문서보다 위에 오고,
`java`와 `typescript`를 함께 골라도 하나만 설치된다.
`github`도 같은 방식으로 `git`을 함께 설치한다. PR 템플릿과 GitHub 사용법 문서가 Git 작업 규칙 문서를 가리키기 때문이다.

`--force`를 붙이면 합치지 않고 `AGENTS.md`를 새로 만든다. 고른 프리셋과 그에 필요한 프리셋의 문서·규칙·검증 명령이 들어가고, 사람이 고치거나 더한 내용은 사라진다.
함께 설치하는 프리셋의 규칙과 검증 명령을 `AGENTS.md`에서 다듬어 뒀다면 그것도 원래대로 돌아간다.
파일 덮어쓰기는 직접 고른 프리셋에만 적용한다. `--preset react --force`는 함께 설치하는 `typescript`의 문서나 `.nvmrc`를 덮어쓰지 않고, 그대로 둔 파일을 목록으로 알린다.
그 파일까지 덮어쓰려면 `--preset typescript,react --force`처럼 프리셋을 직접 적는다.

### 0.6 이하에서 올릴 때

0.6 이하는 프리셋 문서를 `docs/` 한 층에 설치했다(`docs/workflow.md`). 0.7부터는 `docs/<프리셋 이름>/` 아래에 설치한다(`docs/git/workflow.md`).
`init`은 기존 파일을 옮기거나 지우지 않으므로, 옛 저장소에서 다시 실행하면 옛 문서는 남고 새 위치에 같은 문서가 또 생긴다.
둘 다 문서 지도에 올라 `check`는 통과한다. 그래서 `init`이 옛 위치에 남은 문서를 새 위치와 함께 알린다.

```text
설치 위치가 바뀐 프리셋 문서와 이름이 같은 문서 3개가 옛 위치에 있습니다.
이전 버전이 설치한 문서라면, 고쳐 쓴 내용을 새 위치로 옮긴 뒤 옛 파일을 지우세요. 직접 쓴 문서라면 그대로 두면 됩니다.
옛 파일을 지웠으면 AGENTS.md 문서 지도에서 그 줄도 지우세요.
위에서 건너뛴 파일이 옛 경로를 안내하면 그 파일을 지우고 다시 설치하세요.
  docs/workflow.md → docs/git/workflow.md
  docs/github.md → docs/github/usage.md
  docs/lint-and-ci.md → docs/java/lint-and-ci.md 또는 docs/typescript/lint-and-ci.md (내용을 보고 고르세요)
```

- 파일 이름만 보고 찾는다. `docs/testing.md`처럼 흔한 이름은 직접 쓴 문서일 수 있으므로, 이전 버전이 설치한 문서인지 확인하고 정리한다.
- 고른 프리셋(과 그에 필요한 프리셋)의 문서만 알린다.
- 셋째 줄은 기존 `AGENTS.md`에 합쳤을 때만 나온다. `--force`로 새로 만들었으면 옛 줄이 없다. 이때 옛 문서는 지도에 없는 문서가 되어 `check`가 `unlisted-doc`으로 알린다.
- 넷째 줄은 건너뛴 파일이 있을 때만 나온다. 0.6의 훅과 PR 템플릿은 옛 문서 경로를 적고 있고, 내용이 달라 건너뛴다.

안내가 나오면 아래 순서로 정리한다.

1. 옛 문서를 고쳐 썼다면 내용을 새 위치의 문서로 옮긴다. 프로젝트 방향 문서(`docs/project-direction.md`)는 사람이 채운 문서이므로 반드시 옮긴다.
2. 옛 파일을 지우고, `AGENTS.md` 문서 지도에서 옛 경로의 줄을 지운다.
3. `.githooks/commit-msg`, `.githooks/check-pr`, `.github/pull_request_template.md`가 옛 경로를 안내하면 지우고 `init`을 다시 실행한다.
4. `agentsmd check`로 확인한다.

`docs/lint-and-ci.md`처럼 `java`와 `typescript`가 같은 이름으로 설치하던 문서는 새 위치 두 곳을 모두 알린다. 어느 프리셋의 문서였는지는 내용을 보고 정한다.
옛 문서를 그대로 두고 `check`만 새 버전으로 돌리는 저장소는 손댈 것이 없다.

`spring` 프리셋은 0.7부터 이름이 `spring-java`다. 문서가 Java 문법을 전제해 이름에 언어를 적었다.
`--preset spring`은 설치하지 않고 새 이름을 알린 뒤 종료 코드 2로 끝나므로, `--preset spring-java`로 고쳐 적는다.

```text
알 수 없는 프리셋입니다: spring
spring 프리셋은 이름이 spring-java 로 바뀌었습니다.
```

## agentsmd check

문서 지도(`AGENTS.md`)가 저장소와 맞는지 검사한다. 규칙은 [rules.md](rules.md).

```bash
agentsmd check
agentsmd check --root ../other-repo --docs design
```

| 옵션              | 설명                                                                          | 기본값      |
| ----------------- | ----------------------------------------------------------------------------- | ----------- |
| `--root <경로>`   | 검사할 저장소 루트. 현재 디렉터리 기준                                        | `.`         |
| `--agents <경로>` | 문서 지도 파일. 루트 기준                                                     | `AGENTS.md` |
| `--docs <경로>`   | 문서 디렉터리. 안의 문서는 지도에 모두 있어야 하고 링크도 검사한다. 루트 기준 | `docs`      |
| `--claude <경로>` | Claude Code 지침 파일. 루트 기준                                              | `CLAUDE.md` |

옵션 값이 비어 있으면(`--docs ""`) 검사를 시작하지 않고 `2`를 돌려준다. CI 변수를 그대로 넘길 때 변수가 비어 있는 경우를 잡기 위해서다.

## 종료 코드

| 코드 | 의미                                                   |
| ---- | ------------------------------------------------------ |
| `0`  | 문제 없음 (`init`은 설치 완료)                         |
| `1`  | 규칙 위반이 있음                                       |
| `2`  | 옵션이 잘못됐거나, 프리셋을 모르거나, 문서 지도가 없음 |

CI에서는 `1`과 `2` 모두 실패로 처리된다. `2`는 검사 자체를 시작하지 못했다는 뜻이라 따로 구분한다.
